# 初めて使う人への導入確認

目的は、READMEだけで自分のPythonプロジェクトのライセンス検査を導入できるかを確認することです。この手順を用意しただけでは、ユーザーテスト完了とはしません。

## 準備

このツールを使ったことのない協力者1名以上に、確認対象のコミットSHAとREADMEを渡します。Python 3.11以上・Git・ネットワークが使えるLinuxまたはmacOSと、検査対象のPythonプロジェクトを用意します。

## 課題

1. READMEから、自分のプロジェクトに適した導入方法を選び、最初のHTMLレポートを作る。
2. レポートの対象範囲を説明し、不明または拒否されたパッケージがあれば、その理由を見つける。
3. ポリシーを保存して再検査する。実際に採用してよいライセンス条件はプロジェクトの判断に従う。
4. GitHub Actionsで使う設定を組み立て、失敗時に結果をどこから確認できるか説明する。

最初はREADME以外の説明をせず、迷った場所と時刻を記録します。質問への回答や手助けが必要なら、その内容も記録し、行き詰まったまま待たせる必要はありません。

## 判定と記録

中心となる目標は、前提環境の確認後から「自分のプロジェクトで最初のレポートを生成する」まで10分以内です。取得・インストール・エラー対処も時間に含めます。通信障害や前提環境の不足があれば、時間から黙って除外せず理由を記録します。CIの設定・理解は別の課題として所要時間を記録します。

```text
実施日:
対象コミット:
OS / Python:
プロジェクトの管理方法（pyproject / requirements.txt / その他）:
前提環境の確認:
開始時刻 / 最初のレポート生成時刻:
課題1の所要時間:
検査対象の説明は正しかったか:
拒否・不明の理由を見つけられたか:
ポリシー適用を確認できたか:
CI設定の所要時間と確認結果:
迷ったREADMEの見出し・文章:
発生したエラー:
必要だった手助け:
結果（達成 / 要改善 / 前提不足で再実施）:
```

実施記録を共有する場合は、社内パッケージ名、ローカルパス、認証情報などを除去します。改善後には同じ課題を別の初見の人に試してもらうと、説明を覚えた影響を避けられます。
